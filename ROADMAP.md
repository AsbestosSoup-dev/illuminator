# Roadmap

Tick a box when a step is done. When **every** box under a milestone is ticked, CI requires that
milestone's tests to pass (the `<!-- test: ... -->` tag in its heading names the file in `tests/`).
You can't tick your way past a failing test, and later milestones can't silently break earlier ones.

```
python3 scripts/check.py            # progress + run tests for every finished milestone
python3 scripts/check.py --no-run   # progress only
cargo test --test m00_basics        # work on one milestone at a time
```

Each step is sized for 15-45 minutes. Each milestone ends with something you can *look at*.
Steps marked *(look)* are checked by your eyes; the others are covered by tests.
Milestones without a test tag are manual until their tests are added.

## M0 Pixels on screen <!-- test: m00_basics -->

**Win:** a colour gradient you generated yourself.

- [ ] 0.1 Run `cargo run` and `python3 scripts/check.py` once to prove the toolchain works.
- [ ] 0.2 `src/vec3.rs`: `#[derive(Clone, Copy, Debug, PartialEq)] pub struct Vec3 { pub x, pub y, pub z: f64 }` with `Vec3::new`. Add `pub type Point3 = Vec3;` and `pub type Color = Vec3;`. Uncomment `pub mod vec3;` in `lib.rs`.
- [ ] 0.3 Operators: `Add`, `Sub`, `Neg`, `Mul<f64> for Vec3`, `Mul<Vec3> for f64`, `Div<f64> for Vec3`.
- [ ] 0.4 Component-wise `Mul<Vec3> for Vec3` (you'll use it for colour attenuation in M5).
- [ ] 0.5 Methods `dot`, `cross`, `length_squared`, `length`, `unit` (returns a unit-length copy).
- [ ] 0.6 `src/ppm.rs`: `pub fn write_ppm<W: Write>(out: &mut W, width: usize, height: usize, pixels: &[Color]) -> io::Result<()>`.
  Text format: lines `P3`, `{width} {height}`, `255`, then one `r g b` line per pixel, row-major, top row first.
  Channel value = `(255.999 * c.clamp(0.0, 1.0)) as u8`.
- [ ] 0.7 *(look)* In `main.rs`, render a 256x256 gradient to stdout (red grows left to right, green grows top to bottom, blue 0.25) and view it with `python3 scripts/ppm2png.py out.ppm out.png`.

## M1 Rays, camera, sky <!-- test: m01_rays -->

**Win:** a sky gradient, generated by firing one ray per pixel.

- [ ] 1.1 `src/ray.rs`: `pub struct Ray { pub origin: Point3, pub dir: Vec3 }`, `Ray::new(origin, dir)`, `ray.at(t) -> Point3`.
- [ ] 1.2 On paper: image 400x225, viewport height 2.0, aspect 16:9, focal length 1.0, camera at the origin looking down -z. Work out the viewport's lower-left corner, horizontal vector, and vertical vector.
- [ ] 1.3 `src/sky.rs`: `pub fn sky_color(ray: &Ray) -> Color`. Normalise the direction, `t = 0.5 * (unit.y + 1.0)`, blend white `(1,1,1)` at `t=0` to `(0.5, 0.7, 1.0)` at `t=1`. The ray's length must not matter.
- [ ] 1.4 *(look)* In `main.rs`, build a ray per pixel and write `sky_color` for each.
- [ ] 1.5 *(look)* The top of the image should be blue and the bottom white. If it's flipped, fix your v axis.

## M2 First sphere <!-- test: m02_sphere -->

**Win:** a red disc floating in the sky.

- [ ] 2.1 On paper: expand `|origin + t*dir - center|^2 = r^2` into `a*t^2 + b*t + c = 0`. Write down `a`, `b`, `c`. (Hint: you may want the half-b trick later.)
- [ ] 2.2 `src/sphere.rs`: `pub fn hit_sphere(center: Point3, radius: f64, ray: &Ray) -> Option<f64>`, returning the **nearest root with t > 0**.
- [ ] 2.3 It must handle: a miss (negative discriminant), a sphere entirely behind the ray (both roots negative), a ray starting inside the sphere (use the far root), and an un-normalised `dir`.
- [ ] 2.4 *(look)* Sphere at `(0,0,-1)` radius 0.5, red where hit and sky elsewhere.
- [ ] 2.5 *(look)* Predict first, then try: move the centre to `z = +1`. What do you see, and why?

## M3 Normals and a world <!-- test: m03_world -->

**Win:** a normal-shaded sphere sitting on a giant green planet.

- [ ] 3.1 `HitRecord { pub p: Point3, pub normal: Vec3, pub t: f64, pub front_face: bool }`.
- [ ] 3.2 The outward normal at a hit is `(p - center) / radius`.
- [ ] 3.3 Always store the normal pointing **against** the incoming ray; `front_face` records whether the ray hit the outside. (Decide where this flip lives.)
- [ ] 3.4 Hit tests take a `t_min`/`t_max` window and accept the nearest root inside it, trying the far root if the near one is out of range.
- [ ] 3.5 Decide: `enum Shape` vs `Box<dyn Hittable>`. Write 2-3 lines in `NOTES.md` on what you chose and why.
- [ ] 3.6 `src/world.rs`: `World::new()`, `world.add_sphere(center, radius)`, `world.hit(&ray, t_min, t_max) -> Option<HitRecord>` returning the **closest** hit. Keep `hit_sphere` from M2 alive (delegate to it if you like): M2's tests keep running.
- [ ] 3.7 *(look)* Colour by normal, `0.5 * (n + 1)`. Add a ground sphere at `(0,-100.5,-1)`, radius 100.

## M4 Antialiasing and gamma

**Win:** smooth edges instead of staircases.

- [ ] 4.1 Decide on randomness: `rand` with a **seeded** `SmallRng`, or a tiny hand-rolled xorshift. Seeded means identical renders every run, which is gold for regression checks.
- [ ] 4.2 Take N jittered samples per pixel and average them.
- [ ] 4.3 Pull the camera into `Camera::get_ray(u, v)`.
- [ ] 4.4 Gamma-correct on output (`sqrt` of each channel for gamma 2.0).
- [ ] 4.5 *(look)* Compare against your M3 image zoomed in on the sphere's edge.

## M5 Diffuse materials

**Win:** the first image that makes you say "wait, that looks real".

- [ ] 5.1 Random point inside the unit sphere (rejection sampling).
- [ ] 5.2 Recursive `ray_color(ray, world, depth)`, bouncing at the hit point + normal + random vector. Stop at a depth limit and return black.
- [ ] 5.3 *(look)* Set `t_min = 0.0` and look at the speckled "shadow acne", then fix it with `t_min = 0.001`.
- [ ] 5.4 Switch to a random **unit** vector (true Lambertian) and compare.
- [ ] 5.5 Introduce `Material` with an `albedo`; attenuate with component-wise colour multiplication.

## M8 Parallel rendering

**Win:** the same image in a fraction of the time.

- [ ] 8.1 Add `rayon`.
- [ ] 8.2 Parallelise over rows (`par_iter` / `into_par_iter`, then collect).
- [ ] 8.3 Seed each row's RNG from the row index so parallel output equals serial output exactly.
- [ ] 8.4 Record the speedup in `NOTES.md`.
- [ ] 8.5 Progress feedback on stderr (rows done, or `indicatif`).

## M10 BVH

**Win:** same image, minutes become seconds.

- [ ] 10.1 `Aabb` with the slab ray test.
- [ ] 10.2 A bounding box for every shape, plus merging boxes.
- [ ] 10.3 Build the tree: pick an axis, sort, split at the median. Store nodes in a `Vec` and refer to children by index.
- [ ] 10.4 Traversal with closest-hit pruning (skip boxes farther than the best hit so far).
- [ ] 10.5 Prove the BVH render is pixel-identical to brute force on a small scene.
- [ ] 10.6 Record before and after timings in `NOTES.md`.
